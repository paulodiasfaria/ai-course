Function calling

Um LLM só produz texto. Para agir no mundo (consultar uma base de dados, enviar um email, correr código), descreves-lhe ferramentas e ele responde com um pedido estruturado para chamar uma delas. Quem executa é sempre a tua aplicação, que depois devolve o resultado ao modelo.

ferramentas = [{
    "name": "consultar_encomenda",
    "description": "Devolve o estado, a data prevista e a transportadora de uma encomenda. "
                   "Usa quando o cliente pergunta onde está ou quando chega uma encomenda.",
    "input_schema": {
        "type": "object",
        "properties": {"numero": {"type": "string", "description": "Formato LL-NNNNN"}},
        "required": ["numero"],
    },
}]

r = client.messages.create(model="claude-haiku-5-5", max_tokens=500, tools=ferramentas,
                           messages=[{"role": "user", "content": "Onde está a LL-20931?"}])
# r.stop_reason == "tool_use"
# r.content → [ToolUseBlock(name="consultar_encomenda", input={"numero": "LL-20931"}, id="toolu_...")]

A aplicação executa a função, e envia uma nova mensagem com um bloco tool_result que referencia o id do pedido. O modelo usa o resultado para responder ou para pedir outra ferramenta.

O ciclo de um agente

Um agente é um LLM a usar ferramentas em ciclo, decidindo ele próprio os passos, até concluir a tarefa. O padrão chama-se ReAct (raciocinar e agir). Avança passo a passo neste exemplo:

def agente(pergunta, ferramentas, executar, max_passos=10):
    msgs = [{"role": "user", "content": pergunta}]
    for _ in range(max_passos):
        r = client.messages.create(model=MODELO, max_tokens=2000, tools=ferramentas, messages=msgs)
        msgs.append({"role": "assistant", "content": r.content})
        if r.stop_reason != "tool_use":
            return r.content[-1].text                     # terminou
        resultados = [{"type": "tool_result", "tool_use_id": b.id, "content": executar(b.name, b.input)}
                      for b in r.content if b.type == "tool_use"]
        msgs.append({"role": "user", "content": resultados})
    return "Limite de passos atingido"
Limites

Põe sempre um máximo de passos e um orçamento de tokens. Um agente pode entrar em ciclo, por exemplo a repetir a mesma pesquisa que falha.

Workflows ou agentes?

Nem tudo precisa de um agente autónomo. Um workflow segue caminhos definidos por ti em código; um agente decide o caminho. Os workflows são mais previsíveis, baratos e fáceis de testar. Começa pelo mais simples que resolve o problema.

PadrãoComo funcionaExemplo
Prompt chainingSequência fixa de chamadas, cada uma usa a saída da anteriorExtrair dados → validar → redigir email
RoutingUm classificador escolhe o caminho especializadoFaturação vai para um prompt, avarias para outro
ParalelizaçãoVárias chamadas independentes ao mesmo tempo, depois juntaAnalisar 10 contratos em paralelo; votar entre 3 respostas
Orquestrador-trabalhadoresUm LLM divide a tarefa dinamicamente e delegaPesquisa sobre um tema com subtópicos imprevisíveis
Avaliador-otimizadorUm gera, outro critica, repete até cumprir critériosTradução jurídica revista até não haver erros

Desenhar boas ferramentas

O modelo só sabe o que a ferramenta faz pelo nome, pela descrição e pelo schema. Trata-os como documentação para um colega novo.

  • Nomes e descrições explícitos: quando usar, quando não usar, formato dos argumentos, exemplos.
  • Poucas ferramentas bem escolhidas: 5 ferramentas claras funcionam melhor que 30 sobrepostas.
  • Erros que ajudam: «Encomenda LL-2093 não existe. O formato é LL seguido de 5 dígitos» permite ao modelo corrigir-se; «Erro 404» não.
  • Resultados concisos: devolve só os campos úteis, pagina listas longas. Cada token do resultado volta a entrar no contexto.
  • Ferramentas de alto nível: agendar_reuniao(pessoas, duracao) é melhor do que obrigar o modelo a encadear listar_calendarios, ver_disponibilidade e criar_evento.

Memória

  • Curto prazo: o histórico de mensagens do ciclo atual, incluindo resultados de ferramentas. Em tarefas longas, resume ou remove resultados antigos (compactação).
  • Longo prazo: factos e preferências guardados numa base (vetorial ou relacional) e recuperados no início de cada tarefa, como no módulo 3.
  • Bloco de notas: uma ferramenta para o agente escrever e ler notas (por exemplo um ficheiro de progresso), útil em tarefas com muitos passos.

Executar código em segurança

Dar ao agente uma ferramenta «executar Python» torna-o muito capaz em análise de dados. Também o torna perigoso: o código pode apagar ficheiros, ler segredos ou fazer pedidos de rede, sobretudo se o input do utilizador ou de um documento o manipular.

Verifica o que aprendeste

Em function calling, quem executa a função?

Emails de clientes devem ir para um de três processos fixos conforme o tema. Que padrão usas?

Que resposta de erro de uma ferramenta ajuda mais o agente?

O teu agente de análise de dados vai ser usado por clientes externos. Onde corre o código gerado?

Exercício: desenha as ferramentas de um agente que marca consultas numa clínica.

Uma proposta: procurar_disponibilidade(especialidade, data_inicio, data_fim) devolve até 10 vagas; marcar_consulta(id_vaga, nome, telefone) marca e devolve confirmação; cancelar_consulta(id_marcacao). Descrições com formatos de data, mensagens de erro úteis (vaga já ocupada, sugere as seguintes) e confirmação explícita do utilizador antes de marcar ou cancelar.

Resumo

Com function calling, o modelo pede para chamar ferramentas descritas por JSON Schema e a aplicação executa-as e devolve o resultado. Um agente é este ciclo repetido até o modelo decidir que terminou: pensar, agir, observar. Antes de construir um agente autónomo, vê se um workflow chega (encadear prompts, encaminhar, paralelizar, orquestrar, avaliar e otimizar), porque é mais previsível e barato. A qualidade de um agente depende muito do desenho das ferramentas: nomes claros, descrições completas, erros úteis e resultados concisos. Código gerado pelo modelo corre sempre numa sandbox.
