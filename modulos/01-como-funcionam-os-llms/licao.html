A ideia central: prever o próximo token

Um modelo de linguagem grande faz uma coisa: dado um texto, devolve uma distribuição de probabilidade sobre qual será o próximo pedaço de texto. Gerar uma resposta é repetir esse passo muitas vezes. O modelo escolhe um token, acrescenta-o ao texto e volta a prever.

Tudo o que parece raciocínio, tradução ou programação sai deste objetivo simples, treinado sobre biliões de tokens. Para prever bem a próxima palavra de um contrato, de um teorema ou de um programa, o modelo tem de construir representações internas da gramática, dos factos e da lógica desses textos.

Ideia-chave

O modelo não tem uma base de dados de respostas. Tem parâmetros (pesos) que transformam um contexto numa distribuição sobre o próximo token. Por isso pode inventar factos com total confiança: está a produzir texto plausível, não a consultar uma fonte.

Tokenização

Os modelos não leem caracteres nem palavras, leem tokens: pedaços de texto de um vocabulário fixo, normalmente com 32 mil a 200 mil entradas. O algoritmo mais comum é o Byte Pair Encoding (BPE). Começa com bytes individuais e junta repetidamente o par adjacente mais frequente no corpus de treino, até atingir o tamanho de vocabulário pretendido.

Experimenta abaixo um BPE treinado em tempo real sobre o texto que escreveres. Cada passo junta o par mais frequente.

Consequências práticas que vais sentir no dia a dia:

  • O português gasta mais tokens que o inglês. Os vocabulários são construídos sobretudo com texto inglês, por isso palavras como «desenvolvimento» partem-se em vários pedaços. O mesmo texto pode custar 20 a 50% mais tokens em português.
  • Custos e limites contam-se em tokens. As APIs cobram por milhão de tokens de entrada e de saída, e a janela de contexto (por exemplo 200 mil tokens) também se mede assim. Em inglês, um token anda à volta de 0,75 palavras.
  • Alguns erros vêm da tokenização. Contar letras numa palavra ou fazer aritmética com números longos é difícil porque o modelo não vê os caracteres individuais.

Embeddings

Cada token é um número inteiro (o seu índice no vocabulário). A primeira camada do modelo é uma tabela que converte esse índice num vetor denso, o embedding, com algumas centenas a vários milhares de dimensões. Esta tabela é aprendida durante o treino.

Em PyTorch é simplesmente nn.Embedding(vocab_size, d_model). Ao longo do treino, tokens que aparecem em contextos semelhantes acabam com vetores próximos. À medida que o vetor atravessa as camadas, deixa de representar só o token e passa a representar o token no seu contexto: «banco» numa frase sobre finanças fica num sítio diferente de «banco» numa frase sobre um jardim.

import torch
import torch.nn as nn

vocab_size, d_model = 50_000, 768
emb = nn.Embedding(vocab_size, d_model)

ids = torch.tensor([[812, 4021, 17]])   # 1 frase com 3 tokens
x = emb(ids)                            # forma: (1, 3, 768)
Não confundir

Os embeddings internos de um LLM não são o mesmo que os modelos de embeddings usados em pesquisa semântica (módulo 4). Esses são treinados de propósito para que frases com o mesmo significado fiquem próximas, e produzem um único vetor por texto.

Atenção e o bloco transformer

A arquitetura transformer (Vaswani et al., 2017) resolveu o problema de misturar informação entre posições de forma paralelizável. O mecanismo central é a atenção. Cada token produz três vetores a partir do seu embedding:

  • Query (Q): o que este token procura.
  • Key (K): o que este token oferece para ser encontrado.
  • Value (V): a informação que este token passa a quem o escolher.

A pontuação entre dois tokens é o produto interno da query de um com a key do outro. Depois de um softmax, essas pontuações tornam-se pesos, e a saída de cada token é a média ponderada dos values:

Atenção(Q, K, V) = softmax(Q·Kᵀ / √d_k + máscara) · V

Num modelo de geração, a máscara causal impede cada token de olhar para tokens futuros. A divisão por √d_k evita que o softmax sature quando a dimensão é grande. Passa o rato (ou toca) sobre uma palavra para ver para onde ela olha neste exemplo ilustrativo:

Variantes modernas: MoE, RoPE, KV cache e raciocínio

TécnicaO que resolveComo funciona
RoPEDar noção de posiçãoRoda os vetores Q e K por um ângulo que depende da posição, para que o produto interno dependa da distância relativa. Facilita estender o contexto.
KV cacheGeração lentaGuarda as keys e values já calculados. Cada novo token só calcula a sua própria linha em vez de reprocessar todo o texto.

FlashAttentionAtenção lenta e com muita memóriaCalcula a atenção por blocos dentro da memória rápida da GPU, sem materializar a matriz completa.
Modelos de raciocínioProblemas que precisam de vários passosSão treinados com reinforcement learning para gerar uma cadeia de raciocínio longa antes de responder. Gastar mais tokens a pensar (test-time compute) melhora matemática e programação.

Ciclo de vida: pré-treino, SFT e alinhamento

  • Pré-treino. Previsão do próximo token sobre um corpus enorme. É a fase mais cara (milhões de horas de GPU) e onde o modelo ganha conhecimento e competências. As leis de escala (Kaplan 2020, Chinchilla 2022) mostram que a perda desce de forma previsível com mais parâmetros, dados e computação.
  • Supervised fine-tuning (SFT). Treino adicional com exemplos de conversas no formato pretendido. O modelo base, que só completava texto, passa a responder a pedidos.
  • Alinhamento. No RLHF, humanos comparam pares de respostas, treina-se um modelo de recompensa com essas preferências e otimiza-se o LLM contra ele (PPO). O DPO chega a um resultado semelhante otimizando diretamente sobre os pares, sem modelo de recompensa. Os modelos de raciocínio usam RL com recompensas verificáveis (por exemplo, se a resposta matemática está certa), como o GRPO.
Porque importa

Quando escolhes um modelo aberto no Hugging Face, vais ver versões «base» e «instruct». Para conversar ou seguir instruções usa a instruct. Para fine-tuning próprio (módulo 11), às vezes compensa partir da base.

Amostragem: como o modelo escolhe palavras

Os logits passam por um softmax e dão probabilidades. A forma de escolher o próximo token a partir delas chama-se estratégia de amostragem:

  • Greedy: escolhe sempre o mais provável. Determinístico, mas tende a repetir-se.
  • Temperatura: divide os logits por T antes do softmax. T < 1 concentra a probabilidade nos tokens mais prováveis; T > 1 espalha-a.
  • Top-k: só considera os k tokens mais prováveis.
  • Top-p (nucleus): só considera o menor conjunto de tokens cuja probabilidade acumulada chega a p.

Ajusta a temperatura e o top-p para o contexto «O Porto é uma ...» e vê como a distribuição muda. As barras a cinzento ficam fora do núcleo e nunca serão escolhidas.

TarefaConfiguração típica
Extração de dados, classificação, códigoTemperatura 0 a 0,2
Assistente conversacionalTemperatura 0,5 a 0,8, top-p 0,9 a 0,95
Escrita criativa, brainstormingTemperatura 0,9 a 1,2
Cuidado

Mesmo com temperatura 0 as APIs não garantem respostas idênticas, por causa de não-determinismo numérico nas GPUs e do batching. Se precisas de reprodutibilidade, guarda as respostas.

Exercício: porque é que o KV cache acelera a geração, mas não o processamento do prompt?

No prompt, todos os tokens são processados de uma só vez em paralelo, por isso não há nada para reutilizar. Durante a geração, cada novo token precisa das keys e values de todos os anteriores. Sem cache, seriam recalculados a cada passo (custo quadrático). Com cache, só se calcula a linha do novo token.

Exercício: um modelo MoE tem 47 mil milhões de parâmetros e ativa 13 mil milhões por token. Quanta memória precisa e quanto custa por token?

Precisa de memória para os 47 mil milhões (todos os especialistas têm de estar carregados), mas o custo de computação por token é próximo do de um modelo denso de 13 mil milhões. É por isso que o MoE dá mais qualidade por euro de inferência, à custa de mais memória.

Resumo

Um LLM é um modelo que prevê o próximo token. O texto é partido em tokens, cada token vira um vetor, e uma pilha de blocos transformer usa atenção para misturar informação entre posições. O modelo ganha conhecimento no pré-treino, aprende a seguir instruções no SFT e é alinhado com preferências humanas (RLHF ou DPO). Na geração, a temperatura e o top-p controlam o equilíbrio entre previsibilidade e variedade, e a contagem de tokens determina custo e limites de contexto.
