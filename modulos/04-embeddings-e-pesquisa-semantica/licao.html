De texto a vetor

Um modelo de embeddings é um transformer treinado para que textos com o mesmo significado fiquem perto uns dos outros num espaço de centenas de dimensões. Ao contrário de um LLM, não gera texto: recebe um texto e devolve um vetor, normalmente fazendo a média (mean pooling) dos vetores de todos os tokens da última camada.

São treinados com aprendizagem contrastiva: pares de textos relacionados (pergunta e resposta, título e artigo, frase e tradução) são aproximados, e textos não relacionados do mesmo batch são afastados. O resultado é que «Como devolvo uma encomenda?» fica perto de «Política de devoluções» mesmo sem palavras em comum.

from sentence_transformers import SentenceTransformer

modelo = SentenceTransformer("intfloat/multilingual-e5-base")
frases = ["query: como devolvo uma encomenda?",
          "passage: Tem 30 dias para devolver qualquer artigo sem justificação.",
          "passage: As entregas nos Açores demoram 3 a 5 dias."]
vetores = modelo.encode(frases, normalize_embeddings=True)   # forma (3, 768)
print(vetores[0] @ vetores[1:].T)    # por exemplo [0.86, 0.74]: a devolução fica mais perto
Prefixos

Alguns modelos (família E5, BGE em certas versões) foram treinados com prefixos como query: e passage:. Esquecer os prefixos pode baixar muito a qualidade. Lê sempre o model card.

Similaridade de cosseno

A semelhança entre dois embeddings mede-se pelo cosseno do ângulo entre eles: 1 é a mesma direção, 0 é ortogonal. Com vetores normalizados (norma 1), o cosseno é simplesmente o produto interno, o que torna a pesquisa muito rápida: uma multiplicação de matrizes.

Na demo, cada ponto é um documento num espaço de 2 dimensões (os reais têm centenas). Arrasta a pergunta e vê quais ficam mais próximos em ângulo:

    import numpy as np

def cosseno(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

    Escolher um modelo de embeddings

    O MTEB (Massive Text Embedding Benchmark) compara modelos em dezenas de tarefas e línguas. Filtra por retrieval e pela língua portuguesa, mas confirma sempre com os teus dados, porque a diferença entre domínios é grande.

    Pesquisa lexical com BM25

    O BM25 é o algoritmo clássico dos motores de pesquisa. Pontua um documento pelas palavras da pergunta que contém, dando mais peso a palavras raras (IDF) e saturando a contagem para que repetir uma palavra 50 vezes não valha 50 vezes mais. Não precisa de GPU nem de treino.

    PerguntaBM25Vetorial
    «erro E-4417 na impressora»Encontra o código exatoPode trazer erros parecidos mas diferentes
    «artigo 238.º do Código do Trabalho»ExatoAproximado
    «como despedir um funcionário com justa causa»Falha se o texto disser «cessação do contrato por facto imputável ao trabalhador»Encontra pelo significado
    «carro elétrico barato»Perde «veículo EV acessível»Encontra

    Pesquisa híbrida

    Como cada método falha em casos diferentes, a combinação dos dois quase sempre ganha. O problema é que as pontuações têm escalas diferentes (BM25 vai de 0 a dezenas, cosseno de −1 a 1). A solução mais robusta é o Reciprocal Rank Fusion (RRF), que só usa a posição de cada documento em cada lista:

    def rrf(listas, k=60):
    pont = {}
    for lista in listas:                       # cada lista: ids ordenados
        for pos, doc in enumerate(lista):
            pont[doc] = pont.get(doc, 0) + 1 / (k + pos + 1)
    return sorted(pont, key=pont.get, reverse=True)

    Índices aproximados e bases de dados vetoriais

    Comparar a pergunta com todos os vetores (pesquisa exata ou flat) é ótimo até algumas centenas de milhares de documentos. Acima disso usam-se índices de vizinhos mais próximos aproximados (ANN), que trocam um pouco de recall por ordens de grandeza de velocidade.

    ÍndiceIdeiaCompromisso
    HNSWGrafo em camadas: a pesquisa salta de nó em nó em direção à pergunta, começando numa camada esparsa.Muito rápido e com recall alto; usa bastante memória. É o padrão na maioria das bases.
    IVFAgrupa os vetores com k-means e só pesquisa nos grupos mais próximos.Menos memória; recall depende de quantos grupos visitas (nprobe).
    PQ (product quantization)Comprime cada vetor em poucos bytes.Memória mínima, alguma perda de precisão. Combina com IVF.
    FerramentaQuando usar
    FAISSBiblioteca em memória, sem servidor. Ótima para experiências e lotes.
    ChromaSimples de usar em protótipos, corre embutida em Python.
    QdrantBase de dados vetorial completa: filtros de metadados, pesquisa híbrida nativa, modo local e servidor.
    pgvectorExtensão de PostgreSQL. Se já tens Postgres, evita mais um sistema.
    Elasticsearch / OpenSearchBM25 de referência com suporte vetorial; bom quando já existe.
    Filtros de metadados

    Em produção quase sempre precisas de filtrar: só documentos deste cliente, desta data, desta categoria. Guarda os metadados junto dos vetores e filtra na própria base, não depois de pesquisar.

    Medir a qualidade da pesquisa

    Precisas de um conjunto de perguntas com os documentos relevantes conhecidos. Depois calculas:

    • Recall@k: fração das perguntas em que um documento relevante aparece nos k primeiros. Em RAG é a métrica principal, porque o LLM só vê os k primeiros.
    • MRR (Mean Reciprocal Rank): média de 1/posição do primeiro relevante. Premeia ter o certo em primeiro lugar.
    • nDCG@k: considera vários documentos relevantes com graus de relevância e desconta pela posição.
    def recall_at_k(resultados, relevantes, k):
    return np.mean([len(set(r[:k]) & rel) > 0 for r, rel in zip(resultados, relevantes)])

def mrr(resultados, relevantes):
    rr = []
    for r, rel in zip(resultados, relevantes):
        pos = next((i for i, d in enumerate(r) if d in rel), None)
        rr.append(0 if pos is None else 1 / (pos + 1))
    return np.mean(rr)

    Exercício: quanta memória ocupam 10 milhões de embeddings de 1024 dimensões em float32?

    10⁷ × 1024 × 4 bytes ≈ 41 GB, mais o grafo HNSW (tipicamente 10 a 30% extra). Com quantização para int8 desce para cerca de 10 GB; com quantização binária, para cerca de 1,3 GB, normalmente com uma segunda fase de reordenação com os vetores completos.

    Resumo

    Um modelo de embeddings transforma um texto num vetor, e textos com significado parecido ficam com vetores próximos, medidos pela similaridade de cosseno. A pesquisa lexical (BM25) é imbatível em nomes, códigos e termos exatos; a pesquisa vetorial encontra sinónimos e paráfrases; a combinação das duas (pesquisa híbrida) costuma ganhar. Para milhões de vetores usam-se índices aproximados como HNSW, em bases de dados vetoriais com filtros de metadados. Qualquer escolha deve ser medida com recall@k, MRR ou nDCG num conjunto de perguntas de teste.
